# Adopting distill for an existing CLAUDE.md

How to convert a hand-written `CLAUDE.md` (or any AI-targeted rules file) into a distill-generated one.

This is the migration runbook only. For the rule file format see [README.md § Source rule format](../README.md); for the full behavior contract see [spec.md](spec.md). Neither is repeated here.

## When to use this

You have a `CLAUDE.md` that has grown by accretion — sections added over months, rules buried in prose, no way to reorder or reuse a single rule. Converting it makes each rule an independently editable file and makes the output regenerable.

Do **not** convert a file that is mostly narrative (architecture overviews, onboarding prose). distill compresses rules into bullets; prose comes out worse than it went in.

## Steps

### 1. Choose the source directory

Convention is a `claude-md-rules/` folder next to the output:

| Output | Source |
|---|---|
| `~/.claude/CLAUDE.md` | `~/.claude/claude-md-rules/` |
| `<vault>/CLAUDE.md` | `<vault>/.claude/claude-md-rules/` |
| `<repo>/CLAUDE.md` | `<repo>/.claude/claude-md-rules/` |

The path is arbitrary — `--source` takes any directory — but keeping it adjacent means the banner's `Regenerate:` line stays readable.

### 2. Record a recovery point

The existing `CLAUDE.md` is about to be overwritten. Commit it (or note the SHA) before the first run:

```bash
git rev-parse --short HEAD
```

There is no `--dry-run`; the first `distill` run writes the output file.

### 3. Decide the sections and order ranges

`section:` becomes an `## heading` in the output; `order:` sorts within it. Assign ranges with gaps so rules can be inserted later without renumbering:

```
Purpose          100
Cardinal Rules   200
Structure        300
Critical Rules   400
Task Semantics   500
Conventions      600
Reference        700
```

Sections appear in the output ordered by the lowest `order` they contain, so the ranges also decide section order. Leave 10 between adjacent rules (400, 410, 420 …).

### 4. Split the file — one rule per file

Walk the old file top to bottom and give every distinct rule its own source file. A rule is one thing a reader must do or not do; if a paragraph contains two obligations, it becomes two files.

Name files after their `id`, prefixed by section, so `ls` groups them:

```
cr-read-before-edit.md
cr-search-before-create.md
conv-date-format.md
ref-runbooks.md
```

Each file:

```markdown
---
distill:
  section: Critical Rules
  order: 430
  id: cr-read-before-edit
---
# Rule: read files before editing
## TL;DR
Always read a file before editing it — prevents overwrites.
```

The body is long-form: write the rationale, examples and anti-patterns you want the compressor to have. It compresses to a bullet; it does not copy.

Two things to check as you go:

- **Nothing dropped.** Diff the old file against your rule set by hand — the compressor cannot warn you about a rule you never wrote down.
- **Tables and numbered lists survive.** Structure in the body is preserved in the output, so keep directory trees and decision tables in the rule body rather than flattening them to prose.

Files without a `distill:` block are silently skipped, so a `README.md` inside the source folder is harmless.

### 5. Generate

```bash
distill --source <source-dir> --output <output-file> --title "<H1 text>"
```

`--title` is optional; without it the output starts at the first `## section`. Use it if the old file had a meaningful H1 worth keeping.

Add a Makefile target so nobody has to remember the flags — see [README.md § Make integration](../README.md).

### 6. Verify

- The output opens with the `AUTO-GENERATED by distill` banner carrying `Source:` and `Regenerate:`.
- Every section you defined is present (`grep '^## ' <output>`).
- Run again: the second run should report all rules cached and `0 compiled`.

### 7. Enable edit protection

Install the shipped hook once, if you have not already — see [README.md § Edit protection hook](../README.md) for the install command and the `settings.json` snippet:

```bash
cp hooks/deny-generated-file-edits.sh ~/.claude/hooks/
```

From then on, the newly generated file is protected automatically. Detection is content-based, not path-based: the hook greps any file's header for the `AUTO-GENERATED by distill` banner and, on a match, denies `Edit` / `Write` / `NotebookEdit` and quotes that file's own `Source:` and `Regenerate:` lines back to the agent.

There is no per-file configuration — install the hook once, and every file you convert afterwards is covered the moment its banner exists. This matters more than it sounds: the single most common way to lose work with distill is editing the output, and the hook is what makes that mistake impossible rather than merely documented.

## Gotchas

- **Never hand-edit the output.** Edits are clobbered on the next run. Edit the rule source, then regenerate.
- **Bullet wording is the model's call.** Do not diff output wording between runs expecting stability; assert on sections and rule coverage instead.
- **A `distill:` block missing `section:` is a hard error** (exit 1) — a rule with no section is not silently skipped.
- **Cache is keyed on content.** Editing a rule recompiles only that rule; `--no-cache` forces a full recompile.

## Worked example

Converting a hand-written `CLAUDE.md` in any project or notes directory:

```bash
ROOT=/path/to/project          # or a notes vault, or ~/.claude
mkdir -p "$ROOT/.claude/claude-md-rules"

git rev-parse --short HEAD     # step 2: recovery point

# ... split the old CLAUDE.md into one file per rule ...

distill --source "$ROOT/.claude/claude-md-rules" \
        --output "$ROOT/CLAUDE.md" \
        --title "CLAUDE.md — My Project"
```

A representative run: 25 rules across 7 sections, compiled in 2 chunks, producing a ~7.7 KB output. Re-running immediately reports `25 cached, 0 compiled`.

The result is a file where every line traces back to exactly one source file, and which the edit-protection hook guards without further configuration.

Add a `generate` target so nobody has to retype the flags:

```makefile
SOURCE := $(CURDIR)/.claude/claude-md-rules
OUTPUT := $(CURDIR)/CLAUDE.md
TITLE  := CLAUDE.md — My Project

.PHONY: generate
generate:
	@distill --source "$(SOURCE)" --output "$(OUTPUT)" --title "$(TITLE)"
	@echo "wrote $(OUTPUT)"
```
